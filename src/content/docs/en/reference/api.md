ResiVote provides a REST API under the base path `/api/v1`. The HTTP router is based on the Echo framework and defined in `internal/interfaces/http/router.go`. An OpenAPI 3.0 specification is generated automatically.

## Base Path and OpenAPI Specification

All API endpoints are under `/api/v1`. The OpenAPI specification (`openapi.json`) is generated by `cmd/openapi-gen` from the Echo routes.

```sh
task generate-openapi   # generates openapi.json
task generate-client    # generates Angular API client from openapi.json
```

The Angular client is generated in the frontend with `npm run generate:api` (task `generate-client` wraps both steps).

## Authentication

The API uses Bearer JWT tokens via ZITADEL OIDC. The `AuthMiddleware` validates every request against the ZITADEL JWKS (`{BaseURL}/oauth/v2/keys`) and checks issuer and audience.

- **Token type:** ZITADEL OIDC access token (Bearer)
- **Issuer validation:** `iss` must match `ZITADEL_EXPECTED_ISSUER` (default: `ZITADEL_BASE_URL`)
- **Audience validation:** `aud` must contain `ZITADEL_EXPECTED_AUDIENCE` (default: `ZITADEL_PROJECT_ID`)
- **Dev bypass:** In non-production builds, a signature validation bypass exists that is compiled out in production builds (`-tags production`)

For more details on authentication and ZITADEL, see [Security](../reference/sicherheit/) and [Architecture](../reference/architektur/).

## Tenant Header

Tenant-scoped endpoints require the header `X-Tenant-ID` (UUID) or a tenant slug in the path. The `TenantMiddleware` resolves the user's tenant membership and writes the tenant ID to the request context.

## Middlewares

Middlewares are applied in the following order:

| Middleware | Purpose |
|---|---|
| `Recover` | Panic recovery |
| `SecurityHeadersMiddleware` | CSP, HSTS, X-Frame-Options |
| `BodyLimit` | Request body limit (default `50M`) |
| `CORSMiddleware` | CORS configuration (`CORS_ORIGINS`) |
| `AuditMiddleware` | Audit logging |
| `AuthMiddleware` | JWT validation (ZITADEL OIDC) |
| `TenantMiddleware` | Tenant resolution and membership check |
| `DBTransactionMiddleware` | Request-scoped transaction with `SET LOCAL app.current_tenant_id` (PostgreSQL RLS) |
| `CommunityAccessMiddleware` | Owner access restricted to own communities/units; `tenant_admin` and `meeting_chair` are exempt |
| `MeetingEnabledMiddleware` | Blocks live meeting endpoints when `meeting_enabled=false` |
| `PortalEnabledMiddleware` | Blocks portal endpoints when `portal_enabled=false` |
| `CustomErrorHandler` | Central error handling with `AppError` codes |

## Route Groups

### Public Endpoints

Public endpoints do not require authentication.

| Method | Path | Description |
|---|---|---|
| `GET` | `/health` | Health check (`{"status":"UP"}`) |
| `GET` | `/auth/config` | OIDC configuration (issuer, client ID, post-logout URI); rate-limited (10 req/s, burst 20) |
| `GET` | `/api/v1/checkin/:token/validate` | Check-in token validation (JWT); rate-limited (10 req/s, burst 20) |
| `POST` | `/api/v1/public/contact` | Contact form; rate-limited (5 req/min) |
| `GET/HEAD` | `/api/v1/attachments/:id/slides/images/:imageName` | Public slide image stream for `<img>` tags |
| `POST` | `/internal/demo-reset` | Demo reset (API-key-protected, only when `DEMO_RESET_ENABLED`) |

### Me Routes (`/api/v1/me`)

Authenticated endpoints without tenant scope.

| Method | Path | Description |

| `POST` | `/api/v1/invitations/redeem` | Redeem invitation |

### WebSocket (`/ws/meetings/:meetingId`)

WebSocket endpoint for live updates. Authentication and tenant/community access checks are applied during the upgrade handshake.

| Method | Path | Description |
|---|---|---|
| `GET` | `/ws/meetings/:meetingId` | WebSocket upgrade |

<Aside type="note" title="WebSocket Configuration">
  Ping/pong cycle: `WS_PONG_WAIT` (60s), `WS_PING_PERIOD` (54s), `WS_WRITE_WAIT` (10s). Buffer sizes: `WS_READ_BUFFER_SIZE` (1024), `WS_WRITE_BUFFER_SIZE` (1024). Max message size: `WS_MAX_MESSAGE_SIZE` (4096). In production, browser origins are checked against `CORS_ORIGINS`; in development, all origins are allowed.
</Aside>

WebSocket messages transmit live meeting status, voting progress, and quorum updates.

### Static Files

The Angular frontend assets are embedded via `embed.FS` and served via Echo static files (`dist/browser`). Paths not found fall back to `index.html` (SPA routing, HTML5 History API).

## Error Handling

The `CustomErrorHandler` converts `AppError` instances into structured JSON responses. Each error contains a machine-readable `code` and a `message`.

| Code | HTTP Status | Description |
|---|---|---|
| `NOT_FOUND` | 404 | Resource not found |
| `CONFLICT` | 409 | Conflict (e.g. state transition) |
| `VALIDATION_ERROR` | 400 / 422 | Validation error |
| `UNAUTHORIZED` | 401 | Not authenticated |
| `FORBIDDEN` | 403 | No permission |
| `TENANT_MISMATCH` | 403 | Cross-tenant access |
| `INVALID_STATE_TRANSITION` | 409 | Invalid state transition |
| `QUORUM_NOT_MET` | 409 | Meeting not capable of passing resolutions |
| `VOTE_NOT_ALLOWED` | 403 | Voting not allowed |
| `PROXY_INSTRUCTION_VIOLATION` | 409 | Proxy instruction violated |
| `ALREADY_VOTED` | 409 | Already voted |
| `NOT_CHECKED_IN` | 403 | Not checked in |
| `MEETING_NOT_OPEN` | 403 | Meeting not open |
| `AGENDA_ITEM_NOT_OPEN` | 403 | Agenda item not open |
| `USER_NOT_LINKED` | 403 | User not linked |
| `INTERNAL_ERROR` | 500 / 503 | Internal error |
