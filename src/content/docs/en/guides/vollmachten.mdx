This guide describes how proxies (powers of attorney) work in ResiVote. It is intended for tenant administrators, meeting chairs, and owners.

## Proxy

A proxy transfers the voting right for a specific unit and meeting from one owner to another. It consists of the following:

- **Grantor** – the owner granting the proxy.
- **Grantee** – the owner receiving the proxy.
- **Unit** – the unit for which the proxy applies. Proxies are unique per unit and meeting.
- **Meeting** – the meeting to which the proxy refers.

An owner cannot authorize themselves. Only one active proxy is allowed per unit and meeting.

## Proxy Scope

The scope of a proxy can be:

- **Full** – the proxy applies to the entire meeting. The proxy may vote on all agenda items.
- **Restricted** – the proxy is limited to specific agenda items. The system checks whether an agenda item is covered: always for full scope, for restricted only if an instruction exists for the agenda item.

## Instructed Voting (Instructions)

For restricted proxies, each instruction defines a mandatory vote for a specific agenda item:

- **Agenda item** – the agenda item to which the instruction applies.
- **Mandated vote** – the prescribed voting option (yes, no, abstain, a specific candidate, or free text).

<Aside type="caution" title="Binding Instruction">
  An instructed vote is binding. The proxy must vote in accordance with the instruction. The system enforces this at the time of voting.
</Aside>

## Grant a Proxy

<Steps>

1. **Meeting in the correct state.** Proxies can only be created while the meeting has the status published, check-in, in progress, or open. Creation is blocked in draft, closed, or archived.

2. **Verify owner and unit.** The system verifies that the grantor actively owns the unit and that the unit belongs to the community scope of the meeting. The proxy must be a legitimate owner in the meeting's communities. For MEG units, MEG delegates without direct ownership in the MEG community may also be authorized as proxies.

3. **Define scope and instructions.** Choose full or restricted. For restricted, add an instruction per agenda item with the mandated voting option.

4. **Save the proxy.** The system creates the proxy and immediately updates attendance and the live quorum, since the representation changes.

</Steps>

## Revoke a Proxy

A proxy is revoked by setting a revocation timestamp; the proxy is then no longer active. A revocation also immediately updates attendance and the live quorum.

## Representation During Voting

During voting, the system automatically takes active proxies into account:

- The proxy must be present at the meeting themselves (checked in under any unit) for the representation to count.
- When the proxy votes for a represented unit, the vote is recorded for the proxy and references the proxy.
- If the owner is directly present (physical presence), this takes precedence over the proxy — the owner votes themselves.
- The same rules apply to analog voting: if the unit is not checked in but is represented by an active proxy and the proxy is present, the proxy votes.

## Representation at Check-in

Proxies automatically affect attendance. Represented units are marked as represented, provided the proxy is present somewhere in the meeting. The represented unit is included in head vote and value quota calculations. For details, see the guide <a href="/guides/checkin/">Check-in and Attendance</a>.
