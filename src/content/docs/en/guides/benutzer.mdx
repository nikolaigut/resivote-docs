ResiVote separates the authentication identity from the ownership identity. Roles are stored per tenant in the database, not derived from login claims. All data is tenant-isolated.

## User vs Owner

ResiVote deliberately decouples the login identity from ownership:

- **User** – the authentication identity. Contains the external identity, email, name, and a role. The tenant reference is nullable (not set for super admins).
- **Owner** – the ownership identity. Contains name, email, phone, and an optional link to a user account. An owner can own units in multiple communities within the same tenant.

The linking happens on first login: the system links the external identity to all user records with the same email that do not yet have an external identity.

### Owner Properties

| Field | Meaning |
|------|-----------|
| External identity | Global identity (cross-tenant) |
| User reference | Optional link to a user account (nullable for legacy data) |
| Archived | Owner marked as archived |
| Tenant | Owners can only own units within the same tenant |

## Roles

ResiVote has four roles:

### Tenant Admin

The tenant administrator prepares meetings, invites participants, manages communities and units, and takes the minutes. They only see data from their own tenant.

### Super Admin

The super admin is global. They manage tenants, have access to super admin routes, and can impersonate users. The super admin role is a global claim, not stored per tenant.

### Meeting Chair

The chair leads the meeting via the chair dashboard: opens and closes agenda items, starts votes, grants quorum overrides, and controls live result visibility.

### Owner

The owner participates in meetings, votes, and views their documents in the portal. The owner role is the default role for voting-eligible persons.

## Tenant Assignments

Tenant role assignments are the source of truth for tenant access — not login claims. A user can have multiple entries, one per tenant.

<Aside type="caution" title="Super admin not stored here">
The super admin role is deliberately not stored in tenant role assignments. It remains a global claim, since super admins operate across tenants.
</Aside>

Allowed roles per tenant: tenant admin, meeting chair, owner.

## Tenant Isolation

ResiVote is multi-tenant. Every entity carries a tenant reference:

- Owners are tenant-specific.
- Documents are tenant-isolated.
- Folders are tenant-isolated.
- Meetings belong to a tenant.
- Audit logs are tenant-isolated.

Super admins operate globally. All other users only see data from their own tenant. Tenant isolation is enforced at the database level and at the application level.

## Managing Owners

Owners are voting-eligible persons or organizations that own one or more residential units. They are recorded with name, address, and email, and assigned to the corresponding units via ownership records.

An owner can own units in multiple communities within the same tenant. The ownership shares determine the value quota. Each unit has a primary voter.

Archived owners are hidden in administration but retained for historical minutes.

## Proxies

An owner can authorize another person with a proxy to attend the meeting and vote on their behalf. Proxies can be granted as full or instructed.

The system ensures that only the proxy votes digitally — the grantor is blocked as long as an active proxy exists. Instructed votes must match the instruction.

## Impersonation

Super admins can assume the identity of another user. The process uses ZITADEL token exchange:

- The super admin exchanges their access token for a new token that assumes the target user's identity.
- The resulting token identifies the impersonator.
- Every action during impersonation is logged in the audit log with the impersonator's identity.

<Aside type="note" title="Full Traceability">
Impersonation is fully traceable in the audit log. The hash chain binds the impersonator identity into every audit entry.
</Aside>

## Securing Access

Every user logs in via ZITADEL. Authentication is done via personal links or invitation codes. Tenant administrators only see data from their own tenant.
