ResiVote gestisce i documenti in una struttura gerarchica di cartelle per comunità. Tutti i file vengono salvati cifrati. L'importazione dei regolamenti estrae metadati e unità dai PDF tramite IA.

## Entità documento

Ogni documento rappresenta un file nel portale dei proprietari. L'accesso viene controllato tramite la cartella associata.

| Campo | Significato |
|------|-------------|
| Mandante | Mandante (isolamento multi-tenant) |
| Comunità | Comunità (nullable per cartelle a livello di mandante) |
| Cartella | Cartella superiore (obbligatorio) |
| Nome | Nome visualizzato |
| Categoria | Categoria (normalizzata) |
| Nome file | Nome file pulito |
| Tipo MIME | Tipo MIME |
| Dimensione | Dimensione del file |
| Non letto | Flag non letto |

### Categorie di documenti

La categoria viene normalizzata e validata rispetto ai valori consentiti: verbale, invito, conto annuale, regolamento, avviso, modulo e altro. I valori non validi vengono impostati su «altro».

### Pulizia del nome file

Il sistema pulisce il nome file rimuovendo le componenti di percorso e sostituendo i caratteri pericolosi. I nomi vuoti vengono impostati su un valore predefinito. Questo impedisce l'accesso a percorsi non autorizzati.

## Entità cartella

Le cartelle formano una struttura gerarchica all'interno di una comunità o di un mandante.

| Campo | Significato |
|------|-------------|
| Comunità | Comunità (nullable per cartelle a livello di mandante) |
| Cartella superiore | Cartella superiore (nullable per la root) |
| Proprietario | Proprietario per cartelle personali (nullable) |
| Nome | Nome della cartella |
| Visibilità | Pubblica o riservata |
| Percorso | Percorso completo (p. es. `Rapporti annuali/2024`) |
| Numero di documenti | Numero di documenti |

### Visibilità

- **Pubblica** – visibile a tutti i proprietari della comunità o del mandante.
- **Riservata** – visibile solo al proprietario. Le cartelle personali devono essere riservate.

### Regole delle cartelle

Il sistema costruisce la struttura delle cartelle e valida le regole:

- **Univocità del percorso** – all'interno di una comunità non può esistere un percorso duplicato.
- **Stesso nome in comunità diverse** – consentito, poiché l'univocità è verificata per comunità.
- **Le sottocartelle ereditano la visibilità** – una sottocartella deve avere la stessa visibilità e lo stesso proprietario della cartella madre.
- **La cartella madre deve appartenere alla stessa comunità** – una sottocartella deve trovarsi nella stessa comunità della cartella madre.
- **Cartella personale** – il sistema crea automaticamente una cartella riservata per proprietario, denominata con il nome del proprietario.

### Costruzione dell'albero e conteggio documenti

Il sistema carica tutte le cartelle di una comunità, filtra per utenti non privilegiati (solo cartelle pubbliche e cartelle riservate proprie), costruisce l'albero e riempie il numero di documenti per cartella.

## Backend di storage

Il sistema supporta due backend di storage: filesystem locale e S3/MinIO.

### Dimensione massima upload

La dimensione dell'upload è limitata (predefinito: 50 MB). Il sistema rifiuta i file che superano il limite.

## Cifratura

<Aside type="note" title="Encryption at Rest">
Ogni documento viene cifrato prima del salvataggio. La decifratura avviene solo in caso di download autorizzato. Lo storage non contiene mai testo in chiaro.
</Aside>

### Strati

La cifratura consiste in due componenti:

1. **Gestione delle chiavi** – gestisce le chiavi di cifratura dei dati per mandante. Ogni mandante ha una chiave dedicata, generata e conservata in modo sicuro. Per ogni documento viene derivata una chiave specifica.

2. **Cifratura dei contenuti** – cifra e decifra i contenuti dei file. Ogni file viene cifrato con una chiave di documento e un nonce casuale.

La chiave master viene configurata a livello di sistema.

### Controllo degli accessi

Il sistema verifica per ogni documento:

- **Cartella personale** – solo il proprietario ottiene accesso.
- **Cartella di comunità** – i proprietari devono appartenere alla comunità.
- **Cartella pubblica** – tutti i proprietari del mandante.

## Importazione dei regolamenti

L'importazione dei regolamenti è un processo in due fasi:

```d2
direction: right

"Fase 1: Estrarre" {
  "Caricare il PDF" -> "Estrarre il testo" -> "Pulire il testo" -> "Filtrare il testo" -> "Chiamare l'IA" -> "Analizzare il JSON" -> "Restituire la bozza"
}

"Fase 2: Confermare" {
  "Verificare i dati" -> "Confermare" -> "Creare la comunità" -> "Creare le unità" -> "Importare i proprietari"
}

"Restituire la bozza" -> "Verificare i dati": L'utente modifica
```

### Fase 1: estrarre

<Steps>
  1. **Caricare il PDF** – Il sistema accetta un PDF (max. 50 MB).
  2. **Estrarre il testo** – Il sistema estrae il testo dal PDF.
  3. **Pulire il testo** – Il sistema rimuove i caratteri di controllo.
  4. **Filtrare il testo** – Il sistema conserva solo le sezioni rilevanti (parole chiave in DE/FR/IT/EN, pattern di quote, pattern di unità).
  5. **Chiamare l'IA** – Il sistema invia il testo filtrato al provider IA configurato.
  6. **Analizzare la risposta** – Il sistema analizza la risposta dell'IA, valida i tipi di comunità e i modelli di diritto di voto, scarta le unità senza designazione e tronca a 500 unità.
  7. **Restituire la bozza** – bozza con metadati della comunità, unità e avvertenze. Nessuna operazione di scrittura nel database.
</Steps>

### Fase 2: confermare

<Steps>
  1. **Verificare i dati** – L'utente rivede e modifica la bozza nel frontend.
  2. **Confermare** – Il sistema valida nome e tipo di comunità (STWEG o MEG).
  3. **Creare la comunità** – Il sistema genera la comunità con tutti i metadati.
  4. **Creare le unità** – per ogni unità (designazione, quota di valore, numero di registro fondiario ecc.).
  5. **Importare i proprietari** – opzionale: se è presente un'e-mail o un nome, viene creato un proprietario o associato tramite e-mail, più una quota di proprietà (1/1, votante principale).
</Steps>

<Aside type="caution" title="Nessun rollback automatico">
Se la creazione di un'unità fallisce, la comunità già creata non viene automaticamente cancellata. Il chiamante deve gestire i fallimenti parziali.
</Aside>

### Quorum configurabili tramite regolamento

La comunità contiene tre parametri opzionali del regolamento che sovrascrivono gli standard del tipo di comunità:

| Campo | Significato | Standard (non configurato) |
|------|-------------|-----------------|
| Quorum voti per testa in % | Quorum voti per testa in % | STWEG: 50, MEG: 50 |
| Quorum quote di valore in % | Quorum quote di valore in % | STWEG: 50, MEG: 50 |
| Numero minimo di proprietari | Numero minimo di proprietari presenti | STWEG: 2, MEG: 1 |

Per i dettagli sul calcolo del quorum si veda `/guides/quorum/`.

### Limitazione del diritto di voto (Art. 712g ZGB)

La comunità contiene due parametri per la limitazione regolamentare del diritto di voto:

- **Attivazione** – predefinita disattivata. Deve essere attivata esplicitamente.
- **Percentuale** – predefinita 50%. Limita i voti per testa di un proprietario se la sua quota sul valore totale supera la percentuale.

Il sistema marca i proprietari interessati e segnala che la limitazione è stata applicata.
